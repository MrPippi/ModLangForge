# 模組橫幅、下載量與目錄顯示切換：設計

日期：2026-10-17

## 目的

玩家逛模組目錄時，第一眼最想知道兩件事：**這個模組翻譯了多少**、**這個模組有多熱門**。現在的卡片用一條粗框、像素分格的大進度條表示翻譯進度，佔了很多版面，卻沒有熱門程度的資訊，卡片之間也缺少能一眼認出模組的圖像。

這次要：

1. 在模組卡片與模組頁加上 Modrinth 的橫幅圖片，讓目錄更好認、更好看。
2. 顯示模組在 Modrinth 上的總下載次數。
3. 把翻譯進度改成清楚的小標籤／一行文字，拿掉大進度條。
4. 模組目錄可以在「卡片」與「條列」兩種顯示方式之間切換。

## 目標

- 卡片與條列都能一眼看到翻譯進度與下載量。
- 翻譯進度仍然醒目，但不再用大進度條佔版面。
- 有橫幅的模組在卡片與模組頁顯示橫幅；沒有橫幅的模組版面一樣整齊。
- 玩家選的顯示方式會被記住。

## 非目標

- 不追蹤玩家在本站下載資源包的次數（使用者確認 Modrinth 的下載次數可行，就不做本站計數）。
- 不顯示 CurseForge 的下載次數（需要 API Key，且只有部分模組只上架 CurseForge）。
- 首頁「最近更新」「等你校對」等區塊不改版：它們本來就是精簡條列、沒有進度條。
- 不改動「翻譯依據的模組版本」側欄裡各版本的百分比小字。
- 不在網頁執行時連到 Modrinth：橫幅與下載量都在建置前抓好、放在本站。

## 反目標（做了反而失敗的情況）

- 翻譯進度變得難找、或比下載量還不顯眼。
- 有橫幅與沒橫幅的卡片高度或排版不一致，目錄看起來參差不齊。
- 網頁在瀏覽時向 Modrinth 載入圖片或資料（會洩漏訪客資訊，也需要放寬內容安全政策）。
- 橫幅讓目錄頁明顯變慢（圖片過大、沒有延遲載入）。

## 使用者決定的設計

以下都是使用者在討論中看過示意圖後選定的。

### 卡片模式（模組目錄預設）

- 卡片上方是橫幅：模組在 Modrinth 上被作者設為「精選」（featured）的展示圖片；沒有精選圖片時，改用第一張展示圖片（使用者選擇，讓有橫幅的模組多一些）。
- 不適合當橫幅的圖片（例如設定畫面、文字截圖）可以個別針對模組停用橫幅，停用後就當作沒有橫幅。
- 模組圖示疊在橫幅左下角。
- **翻譯進度做成橫幅右上角的小標籤**，例如「翻譯 92%」，以顏色區分完成度。原本卡片底部的進度條拿掉。
- 下載量放在簡介下方一行，例如「⬇ 9,840 萬次下載」。
- 版本與載入器維持在卡片最下面一行小字。
- **沒有橫幅的模組**：用符合網站風格的花紋填滿橫幅區域，進度標籤一樣放在右上角，讓所有卡片高度一致。

### 條列模式

- 一列一個模組，由左到右：模組圖示、名稱與中文名、一行簡介、版本與載入器小字；最右側是翻譯標籤與下載量。
- 條列模式不顯示橫幅。

### 顯示方式切換

- 模組目錄右上角有「卡片／條列」切換按鈕。
- 網站記住玩家上次選的方式（存在該瀏覽器，不需登入）；預設為卡片模式。

### 翻譯完成的模組

- 翻譯 100% 時，標籤顯示綠色的「✓ 完整翻譯」，而不是「100%」。
- 未滿 100% 顯示「翻譯 N%」，顏色依完成度區分。
- 「完整翻譯」只代表每句都有中文，不代表有人校對；原本的翻譯狀態標籤（機器翻譯／部分校對／已校對）保留，以小字放在名稱附近。

### 模組頁

- **頁面最上方放橫幅**，模組圖示疊在橫幅左下角。沒有橫幅的模組不顯示橫幅區塊（不用花紋），頁首維持現在的樣子。
- 下載區塊的翻譯進度改成一行文字加一條細線，例如「翻譯 92% · 已翻譯 1,234 / 1,340 條」；100% 時顯示「✓ 完整翻譯」。
- 手冊進度用同樣樣式，例如「手冊 75% · 3 / 4 段」。
- 資訊欄新增一行「Modrinth 下載量」。

## 限制

- 網站是靜態建置後部署在 Cloudflare Workers；建置流程（Workers Builds）不應依賴當下連得到 Modrinth。
- 每個版本的靜態檔案上限是 20,000 個（CI 超過 15,000 會警告）。橫幅每個模組最多一張，目前約 100 個模組，影響很小。
- 內容安全政策（CSP）目前只允許本站圖片與少數來源，不應為了橫幅放寬。
- 網站文字要用玩家熟悉的說法（例如「整合包」「合併資源包」），避免技術術語。
- 模組圖示已有同樣的做法：`scripts/fetch-mod-icons.ts`（`npm run icons:fetch`）從 Modrinth 下載、用 `sharp` 轉成 WebP，存到 `apps/site/public/mod-icons/<modId>.webp`；`apps/site/src/lib/data.ts` 與 `lib/modIcon.ts` 依檔案是否存在決定網址。

## 我（設計者）的決定，使用者可推翻

- **橫幅抓取方式**比照模組圖示：新增抓取工具，下載 Modrinth 專案的精選展示圖片，縮成適合卡片與模組頁的寬度並轉成 WebP，存在 `apps/site/public/mod-banners/<modId>.webp`；只接受 `cdn.modrinth.com` 的圖片並設大小上限。挑選順序：精選圖片 → 第一張展示圖片（依 Modrinth 的排序）→ 沒有橫幅。
- **停用個別模組的橫幅**：用一份停用清單（列出 modId）讓抓取工具跳過該模組，並刪除已存在的橫幅檔；清單放在版本控制內，誰都看得到為什麼某個模組沒有橫幅。
- **下載量存放**：存成一份獨立的資料檔（每個模組的下載次數與抓取日期），不寫進各模組的 `mod.json`，避免和人工維護的資料混在一起。
- **下載量更新**：交給每週的自動追蹤流程（Track mod versions）一起更新並開 PR，所以數字最多慢一週；本機也能手動執行。
- **數字寫法**：用中文的「萬／億」簡化，例如「9,840 萬」「3.1 億」；一萬以下直接顯示完整數字。
- **只上架 CurseForge 的模組**：不顯示下載量那一行，也不顯示「0」。模組對應的 Modrinth 專案沿用 `mod.json` 的 `links.modrinth`（`modrinthSlug`，與圖示工具相同）；沒有 Modrinth 連結的模組在下載量資料檔裡沒有項目，不算錯誤。
- **更新頻率與失敗處理**：下載量由每週的自動追蹤流程一併更新；Modrinth 暫時連不到或個別模組查詢失敗時只記警告、保留舊數字，不讓整個流程失敗。橫幅和模組圖示一樣只在手動執行工具時更新（加 `--force` 才重新下載），避免每週的 PR 出現大量圖片變更。
- **資料檢查**：下載量資料檔納入 `npm run validate:data` 檢查（格式、數字為非負整數、modId 必須是已收錄的模組）。
- **整合包頁**：「整合包文字」「任務」進度同樣套用「✓ 完整翻譯」的規則。
- **顯示方式的初始畫面**：伺服器先輸出卡片模式；記住的是條列時，在瀏覽器端切換。實作者應盡量避免明顯的版面跳動。
- **排序**：模組目錄的排序選單新增「下載量」選項；預設排序不變。
- **進度條元件**：整合包頁面的「整合包文字」「任務」進度也改用同一種新樣式（一行文字加細線），全站一致。
- **進度標籤顏色**：沿用網站既有的配色變數，分成「完整翻譯」「大部分已翻譯」「還有很多沒翻」幾級；確切門檻交給實作者，與現有翻譯狀態的顏色協調即可。

## 留給實作者

- 橫幅輸出的確切尺寸、裁切方式與 WebP 品質（需兼顧卡片與模組頁的清晰度和檔案大小）。
- 沒有橫幅時的花紋樣式（要符合網站現有的像素風格）。
- 卡片與條列在手機寬度下的排版細節。
- 記住顯示方式的實作（例如 localStorage），以及讀不到時退回預設的處理。
- 橫幅圖片的延遲載入與替代文字。
- 下載量資料檔的格式、位置與驗證方式。
